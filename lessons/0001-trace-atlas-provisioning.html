The bridge is compute_environment.tier.default_atlas_tier. For example, latestcommit routes to the testing Atlas project, while production routes to prod. This is defined in environment-data.

DMO declares dmo-demo with compute tier demo. The client-locals module derives its testing Atlas project. The client core state creates that project, its Azure Private Link, then the shared cluster.

Dedicated namespaced cluster path

Filternamespaces_to_create_atlas_persistence

The default cluster name is {subbrand}-{tier-shortName}-{app}. Thus a DMO latestcommit pricing namespace becomes dmo-lc-pricing. The final replica-set module sets topology, autoscaling, backups, tags, and termination protection.

A namespace using mongo_databases_in_atlas_cluster does not create another cluster. It creates a database-scoped user and connection string against an existing shared cluster. MongoDB creates the database on first write.

3. How users reach different clusters

An Atlas database user belongs to a project. Its scopes can then restrict it to a named cluster, while its roles restrict what databases it can access.

User kindAuthenticationScope and role
Dedicated applicationBlue/green username and passwordOne cluster; readWriteAnyDatabase
Shared-cluster applicationBlue/green username and passwordOne cluster and readWrite on one database
AKS workloadAzure workload OIDCDerived from the same application-access map; no stored password
Human workforceEntra group OIDCProject-wide; prod makes only client admins writers and other groups readers
Data platformBlue/green username and passwordCluster-wide read-only access

Blue/green rotation keeps two Terraform-managed users. One is active while the other can rotate; connection strings point to the active credentials in Azure Key Vault. Read the rotation module and MongoDB’s database-user model.

4. Client, tenant, and banner

Client is the main infrastructure boundary: DMO, AHX, KFL, and so on. It commonly has its own resource group, AKS cluster, vaults, and tiered Atlas projects.

Banner is the retail operating brand inside a client. Terraform calls it subbrand. AHX, for example, contains banners such as ADAB and ADDL. The pair subbrand + compute tier forms a compute environment and influences namespace, cluster, vault, and tag selection.

Tenant is not a general first-class configuration object in this repository. In application discussions it usually means a runtime consumer sharing a multi-tenant service; in Azure code, tenant_id means the Entra directory. Never infer which meaning is intended. Generic subbrands such as rtls or kfl deliberately support resources shared by several banners.
